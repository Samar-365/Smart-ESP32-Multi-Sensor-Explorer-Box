Software Requirements Specification (SRS)
Smart ESP32 Multi-Sensor Explorer Box — Web Dashboard

Version: 1.0
Project Type: IoT-Based Environmental Monitoring System
Platform: Web Application
Primary Device: ESP32 Multi-Sensor Explorer Box

1. Introduction
1.1 Purpose

The purpose of this web application is to provide a simple and user-friendly dashboard for monitoring and analyzing data collected by the Smart ESP32 Multi-Sensor Explorer Box.

The ESP32 collects environmental data from multiple sensors, processes the readings, and transmits the data through Wi-Fi to a cloud/backend system. The website provides remote access to this information through a web browser.

The project's existing architecture follows the flow:

Sensor Sampling → Data Processing → Local Display → Wi-Fi/REST → Cloud → Remote User Analytics.

2. Scope

The website will provide the following major functions:

Live Dashboard
Advanced Analytics
Weather Information
Alerts
Device/Cloud Status
Project Information

The website will focus on monitoring and analyzing data from the sensors used in the physical Explorer Box.

The project hardware includes:

BME280
MQ-2 Gas Sensor
LDR
HC-SR04 Ultrasonic Sensor
PIR Motion Sensor
ESP32
TFT display
3. Objectives

The main objectives of the website are:

Display real-time sensor readings.
Provide an overview of the current environment.
Visualize sensor data through graphs.
Analyze historical sensor readings.
Calculate basic statistics.
Detect sensor trends and abnormal readings.
Display threshold-based alerts.
Display live weather information.
Show ESP32 and cloud connectivity status.
Provide a responsive interface for desktop and mobile devices.
4. Users

The system is intended primarily for:

4.1 Student/User

The user can:

View sensor readings.
View graphs.
Analyze historical data.
View alerts.
Check weather.
Check device status.
4.2 Project Administrator

For the basic version, the administrator can additionally:

Set sensor thresholds.
Configure basic system settings.

A complex multi-user administration system is not required for the initial version.

The Analytics section shall allow users to analyze sensor data beyond simply viewing the current readings.

This will be the main advanced feature of the website.

FR-04.1 Sensor Trend Analysis

The system shall display graphs showing sensor readings over time.

Supported parameters:

Temperature
Humidity
Pressure
Gas
Light
Distance

The user shall be able to select a time period such as:

Last hour
Last 6 hours
Last 24 hours
Last 7 days
Custom period
FR-04.2 Statistical Analysis

The system shall calculate basic statistics for numerical sensor data.

For the selected sensor, the system shall display:

Current value
Minimum value
Maximum value
Average value
Standard deviation
Rate of change
Example
TEMPERATURE ANALYSIS

Current       29.6 °C
Minimum       24.1 °C
Maximum       34.2 °C
Average       28.7 °C
Std. Dev.      2.4 °C

Trend: ↗ Increasing
9. FR-04.3 Trend Detection

The system shall identify the general trend of sensor readings.

Possible trends:

Increasing
Decreasing
Stable
Rapidly Changing

Example:

Temperature has increased significantly during the last 30 minutes.

The trend shall be calculated using recently recorded sensor values.

10. FR-04.4 Threshold Analysis

The system shall compare sensor readings with predefined threshold values.

For example:

GAS ANALYSIS

Current Level:     620 ppm
Threshold:         500 ppm

Status: 🔴 HIGH

Threshold Violations: 4
Highest Recorded:     720 ppm

The system shall provide:

Current threshold status
Number of threshold violations
Highest value
Time of latest violation
Time spent above the threshold, where sufficient historical data exists

The project already specifies configurable threshold alerts, including gas spikes and motion detection.

25. Non-Functional Requirements
NFR-01: Performance
Dashboard should load quickly.
Sensor values should update automatically.
Graphs should render smoothly.
Analytics calculations should complete within a reasonable time.
NFR-02: Usability
Interface should be simple and easy to understand.
Important sensor values should be visible on the home page.
Alerts should be visually distinguishable.
Graphs should have clear labels and units.
NFR-03: Reliability
The website should handle temporary loss of ESP32 connectivity.
The last received timestamp should be displayed.
Missing sensor data should not crash the dashboard.
NFR-04: Security
Communication between the website and backend should use HTTPS where applicable.
API keys should not be exposed directly in frontend code.
Sensor data received from external sources should be validated.
NFR-05: Compatibility

The website should support modern versions of:

Google Chrome
Microsoft Edge
Mozilla Firefox
Mobile browsers
